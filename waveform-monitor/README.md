# Waveform Monitor and Comparator

> **Version 1.0** — See [RELEASE_NOTES.md](RELEASE_NOTES.md) for features, bug fixes, and known issues.
> For full installation instructions see [INSTALL.md](INSTALL.md).

## Overview

The **Waveform Monitor and Comparator** is a lightweight Linux microservice designed to ingest, analyze, and compare waveform data over time. The system processes waveform captures in **binary format**, computes signal statistics, tracks signal behavior across captures, and detects potential degradation in waveform characteristics.

The application supports both **command-line workflows** and a **web-based visualization interface**, allowing engineers to inspect waveform behavior, compare up to five signals simultaneously, and generate comprehensive engineering reports.

The system is designed to run on resource-constrained Linux environments such as the **BeagleBone Black** (ARM Cortex-A8, 512 MB RAM). The implementation prioritizes:

- minimal dependencies (Flask, NumPy, Jinja2 — no SciPy)
- float32 sample arrays throughout the pipeline (~50% memory reduction vs float64)
- low-overhead file-based persistence
- sample caps and FFT limits to bound CPU and memory on constrained hardware

# Features

## Binary Waveform Ingestion

Waveforms are provided in **binary format** and parsed before analysis. Two formats are supported:

| Format | Description |
|---|---|
| **WAVE v1** | Custom header format — big-endian float32 samples with source ID, timestamp, sample rate, and units embedded in a 69-byte header. Generated by `scripts/generate_test_waveform.py`. |
| **Raw uint8** | Raw ADC byte stream. Requires a `.meta.json` sidecar file alongside the `.bin` to supply source ID, sample rate, and units. |

Once parsed, waveform data is represented as a float32 sample array with associated metadata: source identifier, capture timestamp, sample rate, and signal units. The original binary files are preserved for traceability.

## Signal Metrics

Each waveform capture is analyzed to compute the following metrics:

| Metric | Description |
|---|---|
| Peak-to-Peak | Max − Min sample value |
| RMS | Root mean square amplitude |
| Mean | DC level of the signal |
| Std Dev | Standard deviation of sample values |
| SNR (dB) | Signal-to-noise ratio via 5-sample moving average residual |
| Dominant Frequency (Hz) | FFT peak bin (DC excluded), computed on up to 131,072 samples |
| Damping Rate (s⁻¹) | Exponential decay rate of the amplitude envelope — positive means attenuating, near-zero means steady state |
| Time Constant (s) | 1 / damping rate — time for amplitude to decay to ~37%; shown when damping rate > 0 |

Metrics are stored to a per-source CSV for trend tracking and report generation.

## Signal Comparison

### Multi-Waveform Comparison (up to 5 signals)

Up to five waveforms can be compared simultaneously. For every pair the system computes:

- **RMSE** — root mean square error after alignment
- **Pearson correlation** — post-alignment similarity
- **Alignment lag (samples)** — time offset detected via FFT-based cross-correlation
- **Phase shift (°)** — lag converted to degrees at the shared dominant frequency (shown when both signals are within 10% of the same frequency)
- **Degradation indicators** — automatic flags for amplitude change >20%, SNR drop >3 dB, frequency shift >10%, or damping rate change >1 s⁻¹

Signals are automatically time-aligned via cross-correlation before error metrics are computed. The cross-correlation is performed once and the result is reused for all downstream metrics, keeping CPU overhead low on the BBB.

### Per-Source Monitoring

New captures can be compared against a reference or historical waveforms from the same source to track long-term signal drift or degradation.

## Visualization

The web interface provides:

- **Waveform Plot** — time-domain signal with correct time axis derived from sample rate and display step
- **FFT Spectrum** — server-computed frequency spectrum (numpy `rfft` on up to 131,072 samples, downsampled to 512 display bins) — no browser-side DFT
- **Signal Metrics Tiles** — all computed metrics including damping rate and time constant
- **Multi-Waveform Overlay** — up to 5 signals overlaid with per-pair RMSE, correlation, lag, and phase shift table
- **Metrics Trend Chart** — key metrics plotted across all captures for a source
- **Difference Plot** — sample-by-sample error between aligned signals

## CLI Support

A command-line interface enables automation and scripting workflows:

```bash
# Ingest a binary waveform
waveform-cli ingest data/raw/sourceA/capture_001.bin

# Compute signal metrics
waveform-cli analyze --input capture_001.bin

# Compare two waveforms
waveform-cli compare --a capture_001.bin --b baseline.bin

# Monitor a directory for new waveform files
waveform-cli monitor --dir ./incoming

# Generate an engineering report
waveform-cli report --source sourceA --output report.html
```

## Engineering Reports

Reports are generated as **self-contained HTML files** with no external dependencies or JavaScript — they render correctly when opened as a local file and print cleanly to PDF.

Each report includes:

| Section | Contents |
|---|---|
| **Signal Health Summary** | Color-coded tiles (good / warn / fault) for overall health, minimum SNR, frequency stability, and amplitude stability across all captures |
| **Per-Capture Metrics Table** | All metrics for every capture: filename, timestamp, sample rate, duration, samples, PTP, RMS, mean, std dev, SNR, dominant frequency, damping rate, time constant |
| **Trend Analysis** | First-vs-last capture delta table showing absolute change, % change, and direction badge (Increasing / Decreasing / Stable) for RMS, PTP, SNR, dominant frequency, and damping rate |
| **Comparison Summary** | RMSE, correlation, alignment lag, and phase shift tiles |
| **Side-by-Side Metrics** | Signal A vs Signal B for every metric with delta column |
| **Degradation Indicators** | Highlighted list of any flagged signal changes |

# System Architecture

```text
Binary Waveform Input (.bin)
           │
           ▼
  Binary Parser / Decoder
  (WAVE v1 float32  ─or─  raw uint8 + .meta.json sidecar)
           │
           ▼
  float32 Sample Array + Metadata
           │
           ▼
  Signal Processing Engine
           │
           ├── Time-domain stats (PTP, RMS, mean, std dev)
           ├── SNR estimation (moving-average residual)
           ├── FFT analysis (dominant frequency, spectrum)
           ├── Damping estimation (envelope peak regression)
           ├── Cross-correlation alignment + phase shift
           └── Degradation detection
           │
           ▼
  File-Based Storage (CSV metrics, JSON comparisons, HTML reports)
           │
           ├── REST API  ──►  Web UI (waveform / FFT / comparison / reports)
           └── CLI
```

# Installation

> Full prerequisites, step-by-step instructions, and troubleshooting are in **[INSTALL.md](INSTALL.md)**.

## Requirements

- Local / dev: Python 3.9+ and pip
- BeagleBone Black: use `scripts/setup_bbb.sh` with the board's Debian-provided `python3`

## Local / Dev Setup

```bash
git clone https://github.com/ahmedalaminn/dcc-6111.git
cd dcc-6111/waveform-monitor

python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

For dev tools (pytest, etc.):

```bash
pip install -r requirements-dev.txt
```

## BeagleBone Black Setup

```bash
chmod +x scripts/setup_bbb.sh run_bbb.sh scripts/reset_demo_state.sh
./scripts/setup_bbb.sh
```

This installs `python3`, `python3-venv`, `python3-pip`, and `python3-numpy` via `apt`, then creates a `.venv-bbb` virtual environment and installs the light Python web dependencies. See [`RUN_BBB.md`](RUN_BBB.md) for the full deployment guide.

The BBB path is designed around the distro Python that ships with the board image. Do not replace the system interpreter or install `requirements.txt` on the board just to reach Python 3.9; use `requirements-bbb.txt` through `scripts/setup_bbb.sh` instead.

# Running the Service

```bash
./run_bbb.sh
```

The web interface will be available at:

```text
http://localhost:8000        # local
http://<bbb-ip>:8000        # from another machine on the same network
```

### Environment overrides

`run_bbb.sh` sets the following BBB-safe defaults. Override any of them at launch:

| Variable | Default | Description |
|---|---|---|
| `MAX_SAMPLES` | 200000 | Global sample limit per waveform |
| `MAX_FFT_SAMPLES` | 131072 | FFT input cap |
| `MAX_ALIGNMENT_SAMPLES` | 50000 | Cross-correlation stride limit |
| `MAX_COMPARE_SAMPLES` | 50000 | Comparison sample cap |
| `MAX_FILE_SIZE_MB` | 64 | Upload size limit |
| `HOST` | 0.0.0.0 | Bind address |
| `PORT` | 8000 | HTTP port |

```bash
PORT=8080 ./run_bbb.sh
```

# Degradation Detection

Signal degradation is flagged automatically when comparing waveforms. Current thresholds:

| Indicator | Threshold |
|---|---|
| Peak-to-peak amplitude change | > 20% |
| SNR drop | > 3 dB |
| Dominant frequency shift | > 10% |
| Damping rate change | > 1.0 s⁻¹ |
| RMSE vs baseline | > 30% of reference RMS |
